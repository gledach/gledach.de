About

gledach is a shelf,
not a platform.

Six free tools, written by the same person, that do not pretend to be one product. Each takes whatever shape suits it: a command you type, a dashboard you open, an API an assistant queries, or just writing. What they share is the promise, not the plumbing.

gledati (slav.): to watch. What a good analyst does before speaking.

What this is

Free, small, and built out of things that already exist.

The home page lists six rules about what every tool promises you. These five are about how they are made, which is the part people usually want to know before they trust one.

Free, and that is the end of it

MIT licensed and public on GitHub. No account, no tier, nothing that turns out to cost money later. Where a tool can do more with a paid key, it says which part and keeps working without one.

As few moving parts as possible

Four of the six install nothing at all: no npm install, no build step, no framework. whenrun, phonehome, signal-patterns and talk are those four. recall ships its own CSV and XML readers rather than pull in two dependencies for forty lines of work. signal needs three runtime dependencies, and that is the heaviest thing on the shelf.

Do not reinvent what already exists

The ones pointed at the outside world read public registers, public feeds and public APIs that were already published. talk reads the TCP table on the machine it runs on. None of it is scraped out of somewhere it should not be, and none of it is a database somebody rebuilt. The work is reading what is there properly and saying how sure it is.

Made for an assistant as much as a person

Four of the six answer an AI assistant directly over MCP: signal, whenrun, phonehome and recall. Each result is structured data with a freshness flag attached, so the assistant can tell a quiet week from a broken collector. talk records on the machine and does not speak MCP. signal-patterns is the writing.

Small enough to copy

Each one is a worked example of a single idea, kept readable on purpose. If you want to build something like this rather than use it, signal-patterns is the written version and every tool here is the code that goes with it.

What they are for

Four questions, six tools, nothing to buy.

Every tool here started as something somebody was checking by hand. If one of the questions below is yours, the tool that answers it is free, runs on your own machine, and takes about fifteen minutes to set up.

Who is moving in my market, and what did I miss?

signal watches eleven public sources around the companies you name: news and Reddit feeds, Hacker News, GitHub releases, YouTube captions, certificate logs, sitemap changes, search interest and more. It scores what it finds, groups the things several publishers corroborate, and answers your AI assistant over MCP. Three of those sources see a move weeks before anyone announces it.

Useful if you do competitive intelligence, product marketing, sales enablement or investing, and you keep finding out late. signal-patterns is the written version if you would rather build your own.

When should this job run so it costs less?

whenrun reads day-ahead electricity prices and the renewable-share forecast, works out the cheapest or greenest window that still meets your deadline, and starts the job there. Backups, builds, an EV charger, a heat pump.

German power can cost three times more in the evening than at midday, and since 2025 every supplier there has had to offer a dynamic tariff. This acts on that without tying you to one supplier's app.

whenrun →

What is my own stuff doing, and is any of it recalled?

phonehome records which domains every device on your network contacts and tells you when one starts talking somewhere new. It blocks nothing and uploads nothing: the job is finding out, which is different from filtering.

recall checks four public registers against a list of the things you actually own: EU product alerts, German medicine shortages, US vehicle campaigns, and software past its security support date. Every match is graded, and a register it could not reach is reported as unreachable rather than clean.

Which API did my coding agent hit, and is it leaking sockets?

talk samples TCP connections on Windows, follows each process up to its parent, and reads the certificate name of a new public host. A long session can open connections and never close them. When the client port range fills, other programs fail in a way that looks like a dead network. talk leaves a record of who, which host, and whether the count is climbing. It does not close a socket.

Seeing it first

Anything worth looking at gets its own subdomain.

You should be able to watch a tool work before you decide to install it. The convention is one address per tool, replaced in place.

Real data, not a mock

The export asks the running viewer the same questions a browser asks and inlines the answers, so a preview cannot drift from the thing it was taken from.

Dated and read only

A snapshot, not a live instance. Nothing you click reaches a database, and every number is true as of the export.

One per tool, replaced in place

A re-export overwrites the preview, so you are looking at the most recent snapshot rather than an archive of all of them.

Generated text is labelled

Battlecards, briefs and convergences are model output, not verified fact. They are a starting point for a person, which is how the tool itself describes them.

Asking for a tool

The queue is public, including what was turned down.

Is there something you keep checking by hand that a tool could watch for you? That is the whole question, and it is worth asking even if the answer turns out to be no.

Three questions decide it

What you check by hand and how often. Where it is published. Whether seeing it needs an account. Those three answers decide whether a thing is watchable at all, so the form asks exactly them and nothing else.

Ask in the open →

Built in order of who it helps

A request that would help more people than the person asking is built first. The open issues are how you check that claim rather than take it on trust, and rejected requests stay visible with the reason attached.

The queue →

In the open, not in an inbox

There is no request address to write to. A request sent privately is invisible to everyone else, cannot be labelled, linked or voted on, and quietly becomes a list only one person can see. The queue is the whole list precisely because there is nowhere else for one to go.
