The collection

Eleven ways in, and three of them speak before anyone announces anything.

Each tile says what the watcher actually reads and how often it runs, not what it promises. The three marked leading hear a move while it is still infrastructure, before anyone has written a sentence about it.

01

Feedsnpm run fetch

Around sixty RSS feeds across the roster and the whole category: Google News, Reddit, vendor blogs, GitHub releases. The list derives from the roster, so retargeting rewrites it rather than leaving it behind.

Alerts arrive in a mailbox, a parser reads them, and the result fills a local inbox database. Two zones, and the second is easy to forget: nothing reaches the dashboard until email:promote runs. The refresh token stays on your machine and is never shipped to the scheduler.

Public certificate transparency, per competitor domain. A new subdomain gets a certificate before the thing on it is announced, which makes this the earliest free view of a vertical launch there is.

Fetch, diff against the last snapshot, emit on new paths, removed paths and rule changes. A page exists before anything links to it.

every 6 h · leading

Through the Algolia search API, filtered on points and recency. Points, comments, author and timestamps arrive as structured fields rather than prose scraped out of a feed summary.

daily

Releases, breaking-change tags and issue complaints. Sixty requests an hour unauthenticated, five thousand with a token.

YouTube captionsnpm run watch:youtube

Captions over HTTP: no audio download and no transcription, which is free for roughly four videos in five. A caption-less video still gets a signal recording that captions were unavailable. Local transcription is opt in.

Why those eleven

Infrastructure moves weeks before the press release does.

The list is not long for its own sake. It is ordered by how early each source speaks, and most monitoring products start at the bottom of it.

  • Infrastructureweeks ahead
  • Hiringmonths, vague
  • Documentationhours
  • Changeloghours
  • Marketingat launch
  • Pressafter

Lead time before a move becomes public knowledge. The three watchers flagged leading above are the three at the top of this chart.

What happens to one item

Five stages between a feed entry and an answer.

The panel below darkens as it goes, which is the point: each stage is one step further from raw data, and the tool reports which one it reached.

Stage 01Classify

Haiku reads the item and types it: product launch, pricing change, funding, customer win, review complaint. With no model key a keyword classifier runs instead, free and less precise, and the method used is recorded on the row either way so you can re-run the ones that matter.

Stage 02Score

Business impact from 0 to 100, re-weighted for this job rather than for news: a product launch outranks generic press coverage, which is the opposite of how a headline ranker would order the same two items.

Stage 03Store

One row, keyed on a hash of its own content, so every write is idempotent and two operators plus a scheduler can run the same pass without producing duplicates. A local file by default. A hosted database only once you point it at one.

Stage 04Correlate

Theme and count rules fire a convergence: a pattern several independent publishers corroborate. A launch, a hiring push and a certificate change all pointing at the same vertical is one finding rather than three unread rows. Each carries a structured citation graph back to its evidence and dedupes per calendar week.

Stage 05Synthesise, and label it

Battlecards from Sonnet, deep research from Opus across a hundred and eighty days of signal, five analyst modes driven by a written persona, and a weekly report that uses no model at all because its arithmetic is deterministic. Every piece of model output is marked as model output, and a claim the evidence does not support is published as unverified rather than asserted quietly.

Who consumes it

Three consumers. The dashboard is only one of them.

The agent surface is what this is built for. A person looking at a dashboard is a second client, and the scheduler is a third.

For agents

Eight tools over MCP

list_companies, search_signals, get_convergences, get_battlecard, list_briefs, get_brief, run_analyst, market_summary, plus signal:// resources for a battlecard or a brief.

Read only by default and not just by convention: the single tool that spends money ships with permission withheld, and opting in binds it to a rolling daily ceiling shared with the scheduler and the command line.

The agent surface

For people

Eight views on localhost

Feed, Battle, Compare, Market, Intel, Report, Briefs and Inbox. Number keys switch mode, a command palette jumps anywhere, and Compare takes an anchor plus up to three rivals in a URL you can share.

Battlecards and briefs come out as markdown you can edit in anything. A regeneration never overwrites the part a person wrote.

For the scheduler

One pass, tiered by cost

A single entry point runs every watcher on the cadence it deserves: the expensive passes weekly, the cheap ones every half hour.

Cadence moves the bill far more than model choice. A job making one model call per tracked company costs four times as much on a six-hourly tier as on a daily one and the output is no fresher. That mistake cost this deployment around two hundred dollars a month before it was caught.

What it costs

There is also a Chrome side panel that checks whatever page you are reading against your own intel, on device. It is experimental, it needs the dashboard running, and the test gate does not cover it. Stated here rather than discovered later.

Point it anywhere

Nothing in here knows which market it is watching.

It ships pointed at thirteen AI coding tools. That is a configuration file, not the product.

Six layers resolve identically: an environment variable, then your local file, then the shipped default. The roster, the feeds, the deal-context axes, subdomain scoring, the agent policy and the answer-engine prompts. Your file is ignored by git, so you can pull upstream forever without a conflict in the one file you changed.

The gate is mechanical rather than a promise: the test suite fails if a brand name appears anywhere outside the configuration directory, or if the dashboard's own labels drift from the roster. Retargeting cannot leave somebody else's market behind in a watcher or a prompt.

npm run doctor       # what worked, and what each missing key unlocks

cp config/companies.default.mjs config/companies.local.mjs
npm run companies    # confirm what is live, and where it came from
npm test             # 15 smoke sections, 5 fixture suites, all offline

That runs offline on a fresh clone, on Windows, macOS or Linux. A model key turns on classification, battlecards and briefs. Without one the keyword classifier runs and everything else still works.

Seeing it first

Anything worth looking at gets its own subdomain.

You should be able to watch a tool work before you decide to install it. The convention is one address per tool, replaced in place.

convention read only 
<tool>.gledach.de

signal.gledach.de     a real deployment, exported to one static file

Real data, not a mock

The export asks the running viewer the same questions a browser asks and inlines the answers, so a preview cannot drift from the thing it was taken from.

Dated and read only

A snapshot, not a live instance. Nothing you click reaches a database, and every number is true as of the export.

One per tool, replaced in place

A re-export overwrites the preview, so you are looking at the most recent snapshot rather than an archive of all of them.

Generated text is labelled

Battlecards, briefs and convergences are model output, not verified fact. They are a starting point for a person, which is how the tool itself describes them.

House rules

What is true of everything on this shelf.

The tools vary. These six do not. They are the reason a tool gets published here at all.

  • Free, and the source is public

    MIT unless a dependency makes that impossible, in which case the licence is stated on the tool's own page.

  • Your machine is the runtime

    Cloud is for sharing state between machines you own. It is not where your data has to live.

  • No account to start

    Clone it and see something real. Keys, hosted databases and schedules are opt in, later, each listed with what it buys you.

  • Honest about blind spots

    Every tool ships a written audit of what it cannot see, kept beside the documentation rather than buried in it.

  • Read only until you say otherwise

    Nothing spends your money because an agent found a button. Paid actions ship disabled and behind a ceiling.

  • Generated text is labelled

    Model output is marked as model output. A tool that cannot tell you what it does not know is not finished.
